# PR 103 review follow-up (2026-10-09)

## Changes in this branch

- SIP calls use an opaque UUID for the Core `call_id`, trace key, log context and debug dump name. The LiveKit room name may contain the caller's number and is used only where the LiveKit API requires it.
- Caller disconnect marks the bridge as closed to further turns and TTS. A confirmation turn still queued by STT is discarded before `handle_turn`.
- SIP hangup ignores a LiveKit `NOT_FOUND` race. Other remove failures trigger deletion of the dedicated call room.
- Restored Clinic Mock snapshots discard expired slots without active appointment references, allowing the baseline slot IDs to be regenerated for the current date.

## Gates outside this fix

- **R-05 / TRANSFERRED:** the current SIP flow ends the call; it does not transfer a caller to staff. Configure a staffed SIP destination and implement and test `transfer_sip_participant` before the W6 transfer demo. No destination is configured in this branch.
- **R-34 / GC-LIVE-04:** the worker has no approved-volunteer number list. Before connecting a PSTN DID, add and verify a fail-closed allowlist at the inbound boundary, populated only with numbers whose owners agreed to take part. The present softphone baseline is not a PSTN launch gate.
- A disconnect that arrives while synchronous Core `handle_turn` is already executing in a thread cannot cancel a Clinic write already in progress. The new guard prevents queued or later turns from starting and prevents later TTS. Test this timing with the real SIP path before PSTN.
